# KubeVirt Builder (from a Clone)

Type: `kubevirt-clone`
Artifact BuilderId: `packer.kubevirt.clone`

The KubeVirt Clone builder creates a customized bootable volume inside a
Kubernetes cluster by cloning an existing DataVolume, modifying it and producing
a new DataVolume and DataSource. It supports both Linux and Windows guests, with
provisioning through SSH or WinRM.

This builder complements other workflows customizing pre-existing images —
the typical day-2 golden image pipeline.

---

## Basic Example

Here is a basic example showing how to clone a Fedora base image and customize it:

```hcl
source "kubevirt-clone" "fedora" {
  kube_config = "~/.kube/config"
  name        = "fedora-customized"
  namespace   = "vm-images"

  source_volume_name = "fedora-base"

  disk_size     = "10Gi"
  instance_type = "u1.medium"
  preference    = "fedora"

  communicator = "ssh"
  ssh_username = "fedora"
  ssh_password = "password"
  ssh_timeout  = "10m"

  media_content = {
    "user-data" = <<-EOF
      #cloud-config
      chpasswd:
        expire: false
      password: password
      user: fedora
      ssh_pwauth: true
    EOF
    "meta-data" = <<-EOF
      instance-id: fedora-customized
      local-hostname: fedora-customized
    EOF
  }
  media_label = "cidata"
}

build {
  sources = ["source.kubevirt-clone.fedora"]

  provisioner "shell" {
    inline = ["echo 'Customization complete'"]
  }
}
```

### Communicator Configuration

The builder defaults to `ssh`. Set it to `winrm` for Windows guests or `none`
to skip provisioning.

The `ssh_bastion_*` and `ssh_proxy_*` options are not supported: the
communicator connects to a port forward on the machine running Packer, which a
bastion host or a proxy cannot reach.
